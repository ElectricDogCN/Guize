# 智能异构边缘计算需求

本需求对应建设待办 [#104](https://github.com/ElectricDogCN/Guize/issues/104)，范围为 `AGENT-EDGE-104`。Guize 持久化计划、授权、调度与最终结果接受；Android 与 Windows/Linux 节点执行有界、版本化任务。

## 共同约束

- 保留原 V1 的27项任务、十项POC、既有需求/验收和GZ-020生产发布义务；本范围的最终组合验收不能替代这些义务。
- MOD-TASK 负责计划和业务接受，MOD-WORKER 负责节点执行；MOD-AI 只提议计划，MOD-IAM/POLICY 控制权限与预算。MOD-EDGE 继续承担网关与ATS，不代替节点运行时。节点不能直接写核心资产数据库。
- Task的consumesContracts、模块列表和producer/consumer映射不授予各模块对契约namespace的直连访问权；实际调用继续受既有owner/consumer许可与逐接口授权约束。CONFIG负责身份接入，身份心跳租约与执行attempt租约分离；WORKER仅按TASK的有限派发读取授权输入，不因此取得ASSET直连、CONFIG/POLICY管理API或核心数据库权限。
- 首期使用本地OpenList经WebDAV承接存储，百度生产接入后置；手机能力以实测为准，首期无需root、AV1硬编或GPU/NPU。ADB用于安装、诊断和测试，不能替代自主平台链路。
- 所有结果绑定真实输入版本、计划/步骤/尝试、fencing、节点、协议与能力包版本和不可变产物摘要。身份心跳不授予素材或任务权限；业务结果只能由平台按事务或条件写接受一次。
- 实际采样集、时间/图像容差、OCR质量和资源阈值消费GZ-011批准版本；测试前固定，不能观测输出后追认阈值。VM注入、真机、短片原型、正式POC和完整产品结果分别记录。

## REQ-EDGE-104-0001

公共执行协议：Android 与 PC 使用同一套任务生命周期。

关联模块：`MOD-TASK`、`MOD-WORKER`。交付任务：`GZ-023`、`GZ-030`；验收：`AC-EDGE-104-0001`。

**条款。** 平台向 Android、Windows/Linux 派发同一语义的有限任务：任务/步骤/计划版本、attempt、节点、单调 fencing、具体输入版本和摘要、输出约束、能力包/执行组、授权、资源预算、优先级及取消方式。节点可使用不同执行后端，但领取、续租、进度、取消确认、结果提交和错误分类必须遵循同一版本协议。注册和身份心跳成功不授予素材读取或任务执行权。

**验收结果。** 同一版本契约用例在 Android 与 PC 两种适配器执行；合法任务正常领取和提交，未知协议/能力、过期授权、错输入/包版本、乱序进度、重复结果、租约过期、重派旧 fencing、取消后结果均产生确定且可查询的拒绝或幂等结果。以平台事务/条件写保证业务结果只接受一次，不承诺节点只执行一次。暂不支持的暂停/检查点须明确声明，不能伪装可迁移任意进程。

**producer → consumer。** MOD-TASK 产生计划、派发及最终接受视图；MOD-WORKER 产生能力/观测/执行事实，Android 与 PC 消费派发；MOD-IAM/POLICY 给出受限授权和预算判定，TASK/WORKER 均验证。GZ-008 承接 `contracts/workers/**`、`workflows/**`、`policies/**`；GZ-006 承接可消费事件，GZ-007 承接持久状态。正式契约留在 Guize 主仓，运行时消费固定版本的 Schema/SDK/制品。

**固定组合验收。** 固定Schema/SDK及同一conformance向量在主仓Windows/Linux运行；Android实际消费/应用构建和设备conformance由GZ-024远端前置完成，不反向阻塞协议交付；重复/迟到/乱序/取消按revision/fencing只接受一次；未知能力、错版本、不可迁移检查点明确拒绝或安全重跑；主交付Task证据与GZ-030同一固定版本组合的实际执行相互引用。

**固定组合验收。** 远端bootstrap不替代应用；真实OnePlus8T可安装并自主走平台网络链路，启停/进度/取消/清理/更新回退可观察；Windows/Linux消费同版协议实际执行，能力来自探测和已验证执行；双方证据绑定真实提交及不可变制品；主交付Task证据与GZ-030同一固定版本组合的实际执行相互引用；增补Android生命周期验收：记录真实机Android版本、target SDK和服务/工作类型；对适用target Android15+后台mediaProcessing验证同类共享6h/24h预算及onTimeout后数秒内停止，对Android16 WorkManager长时Worker验证JobScheduler配额受限分支；实际暂停/取消、短批次安全检查点、租约重派和迟到fencing拒绝可追溯，不能以VM或持续后台假设代替真机结果。

关联模块：`MOD-MEDIA`、`MOD-TASK`、`MOD-WORKER`、`MOD-STORAGE`、`MOD-PLAYER`、`MOD-EDGE`。交付任务：`GZ-025`、`GZ-030`；验收：`AC-EDGE-104-0003`。

**条款。** PC 与已验证手机能力消费同一编码配置和可独立解码单元；平台验证输入/span、执行组、完整覆盖、帧/包、时间戳及产物后封装 HLS，只发布连续 READY 区间。seek 使用独立窗口代数，旧窗口不得覆盖新需求。P0 播放先于 P3 预热和 P6 后台编码；及时性不足时使用已验证源格式或 H.264 兼容路径，不依赖未实测的手机吞吐。

**验收结果。** 实际独立 Worker 编码与 HLS 连续播放/seek、失败单元重派、旧尝试结果拒绝、重复完成、资源保留均有端到端记录；不同执行组的不兼容产物拒绝混装。对 manifest/init/media 及热缓存分别验证 ACL，撤权后命中也拒绝。淘汰临时分片不改变 Asset、正式 Replica 或 Retention。沿用已批准 NFR/POC/固定样本阈值，不在本文另造吞吐或质量数值。

**producer → consumer。** MEDIA 产生编码配置、工作单元和经验证的播放产物；TASK/WORKER 接收执行事实，STORAGE 管临时产物和水位，MEDIA 发布 HLS，PLAYER/EDGE 消费已授权播放引用。MOD-EDGE 仍为网关/ATS，计算运行时归 MOD-WORKER。这是 GZ-021 已合入路线的实施承接，不另建第二套编码调度器。

**固定组合验收。** 实际PC AV1、连续HLS播放/seek、失败重派、覆盖与不兼容执行组拒绝均有平台记录；编码负载下P0容量/公平有效，逐资源和热命中撤权拒绝，兼容回退真实可解码；主交付Task证据与GZ-030同一固定版本组合的实际执行相互引用。

首个端到端结果：10–30秒视频实际解码六帧并入平台。

关联模块：`MOD-ASSET`、`MOD-TASK`、`MOD-MEDIA`、`MOD-WORKER`。交付任务：`GZ-026`、`GZ-030`；验收：`AC-EDGE-104-0004`。

**producer → consumer。** SOURCE/ASSET/IAM 提供受限输入版本；TASK 持久化计划和 attempt；Android 能力包产出元数据/六帧证据；MEDIA/ASSET 验证并建立派生物关系，查询 API/前端消费结果。GZ-013 提供已有 M1 基础，GZ-011 提供样本方法；需显式的跨模块集成交付承接结果接受/查询，不能将“手机本地抽帧”当作平台闭环或全部 GZ-016 完成。

## REQ-EDGE-104-0005

资源预算与有界调度。

关联模块：`MOD-TASK`、`MOD-POLICY`、`MOD-WORKER`、`MOD-OBS`。交付任务：`GZ-027`、`GZ-030`；验收：`AC-EDGE-104-0005`。

**条款。** 编码、解码与 OCR 共用节点容量账本。平台预留和释放 codec 槽、内存、磁盘/临时缓存及适用的 CPU/网络/成本预算，节点只能在本次授权内选择后端、批次和并行度。观测含采样/接收时间、有效期与不可观测原因，过期数据不得继续代表可用容量。质量或采样降级须在任务预先允许的集合内。 可派发预算还须考虑上文适用的 Android 后台时间与 JobScheduler 配额，codec 空闲不等于可继续执行。

**验收结果。** 首个手机分析环境限定一个活动解码/分析 attempt；与 AV1 并发时不能重复承诺同一 codec/内存/空间。分别注入超温、低电、低水位、过期观测、排队超时和失联，确认停止新派发、降并行或有限重派符合预算，且 P0 保留容量和主体公平有效。调整有阈值、冷却和重派预算，不来回振荡；模拟温度只证明策略分支，真实温升另测。对相同素材的静态基线比较完整排队、传输、准备、执行、回传与质量，不用设备标称算力推导收益；具体阈值由样本/设备配置冻结。 同时验证系统额度耗尽或停止时停止新派发、及时停止服务或在短批次安全检查点收口，正确释放预算、有限租约重派并拒绝旧 fencing 结果；真机与 VM 注入分别记录。

**producer → consumer。** WORKER 产生原始观测和资源使用，OBS 统一解释时效；POLICY 产生硬约束与可行性判定，TASK 执行容量预留及调度，节点消费有限执行预算。GZ-008 提供协议，GZ-007 保证预留/扣记/结果接受幂等，后续实际策略和设备控制是实现任务，不用协议文件替代。

**固定组合验收。** AV1/分析并发不重复预留同一codec/内存/盘，失联/取消/重试正确释放或失效预算；冻结负载覆盖资源拒绝、过期观测、冷却、有限重派；VM注入与真实热/功耗测量分别标识；主交付Task证据与GZ-030同一固定版本组合的实际执行相互引用；增补系统执行预算验收：资源可用不代表后台额度可用；对适用Android15+ mediaProcessing共享6h/24h预算、onTimeout停止和Android16 WorkManager/JobScheduler配额耗尽分支，验证停止新派发、暂停/取消、安全短批次检查点释放及有限租约重派，旧fencing迟到结果仍拒绝；真实机记录与VM注入分别注明，阈值/方法仍消费GZ-011批准版本。

## REQ-EDGE-104-0007

受约束的产品 Agent。

关联模块：`MOD-AI`、`MOD-TASK`、`MOD-POLICY`。交付任务：`GZ-029`、`GZ-030`；验收：`AC-EDGE-104-0007`。

**producer → consumer。** AI 产生候选计划/工具选择及解释，TASK 校验并保存 plan/step/attempt、调用受控工具，POLICY/IAM 返回准入判定，WORKER/能力服务消费授权动作，平台接受结果。现有 REQ-V1-0004 是媒体智能加工，不完整覆盖产品 Agent；研发 Harness、Task Spec 或“Agent 修改审批”也不等于这项业务能力。应独立登记新增需求与业务任务，不能用旧 GZ-008/GZ-016 名称隐式取得完整范围。

**固定组合验收。** 同一目标形成可解释可执行计划，失败后有限重规划未完成部分且可查询版本/原因，不覆盖已接受结果与预算；越权工具/超预算/未许可外发/质量降级在派发前拒绝；重放/取消/恢复无重复副作用；主交付Task证据与GZ-030同一固定版本组合的实际执行相互引用。
