# GZ-014 收敛项目交付计划并加固多 Agent 协作一致性

## 背景

GZ-003 已建立需求索引、模块所有权、活动任务登记和协作检查，但合并后复核发现仓库文件、PR 描述和开放 Issue 对 GZ-004～GZ-013 的定义发生漂移。部分 Issue 引用不存在的 `specs/collaboration/**`，GZ-003 Task/ADR 状态也未随合并事实收口。若直接让多个 Agent 开工，会出现同一 Task ID 对应不同目标、公共契约写入者不唯一、错误路径登记和依赖顺序分叉。

## 目标

1. 建立唯一、机器可校验的 Guize V1 Program Plan；
2. 统一 Requirement、Module、Contract、POC、Scaffold、Vertical Slice 的任务 DAG；
3. 明确公共契约 owner/consumer 和共享写入规则；
4. 加固 readiness/coordination 检查，拒绝计划漂移和路径冲突；
5. 收口 GZ-003 Task、ADR、Issue、PR 历史状态；
6. 将 GitHub Branch Protection/Ruleset 保留为显式管理员阻断项。

## 非目标

- 不冻结具体 OpenAPI、Event Payload、DDL、Workflow 业务内容；
- 不实现 Java/Python/前端/Go 业务代码；
- 不执行 POC；
- 不修改生产环境、Secrets、权限或正式数据；
- 不扩大 bootstrap allowlist 绕过 Registry。

- GitHub 外部设置无法由仓库提交代替，必须保留 blocker。
