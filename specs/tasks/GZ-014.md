# GZ-014 合并后生命周期门禁修复实现

## 背景

PR #24 已作为独立 Reservation 合并为 `bb22b4cd8662e6c1ed7d3b63255098d8a74237c1`。本权威分支包含该 merge，Task Spec 与 Active Work 的 `baseSha` 已同步到同一提交，满足实现前置条件。

PR #25 首次 Gate 进一步证明，剩余问题不只是测试调用方式：仓库级无 Task 模式会让 `run-program-lifecycle-gate.py` 把扩展函数回写到 `GUARD.task_ids_from_diff`，而扩展函数又通过同一可变属性调用基础实现，导致无限递归。该缺陷影响真实 main-push 生命周期门禁，不能通过测试规避；必须保存原始基础函数并由扩展函数直接调用，同时补充回归测试。

同一次 Gate 还发现 Task 独占路径中的扩展名为空文件 `Makefile` 未被正文路径解析器识别，导致 Task 与 Registry 的独占路径不一致。正文使用 `./Makefile` 表达，规范化后仍与 Registry 的 `Makefile` 一致。

## 目标

- 最小修复 `scripts/run-program-lifecycle-gate.py` 的无 Task 任务推导递归；
- 保留 wrapper 的精确 diff、POC 和 external blocker 扩展语义；
- main-push 场景允许 wrapper 从完整变更范围推导受影响 Task；
- PR 场景继续显式绑定当前 GZ-014 Task 与分支上下文；
- 补充递归回归测试并修复仓库当前状态集成测试；
- 保持其他生产脚本、Workflow、Makefile 和 Program Plan 不变；
- 刷新 task-bound Evidence，完成 exact-head Gate、fresh Review、expected-head merge 与 post-merge `main` Gate；
- 仅在 post-merge `main` Gate 成功后创建独立 Foundation Completion PR。
