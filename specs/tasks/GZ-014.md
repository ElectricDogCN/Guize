# GZ-014 收敛项目交付计划并加固多 Agent 协作一致性

## 背景

GZ-014 已通过 PR #18 建立 Reservation，并通过 PR #21 将 canonical Program Plan 合入 `main`。PR #21 合并后的独立复审继续发现 Completion、Foundation、依赖时序、外部 Ruleset、任务范围和生命周期转换存在可绕过路径，因此 GZ-014 保持 `in_progress`，在所有阻断项修复、最新 HEAD 复审和独立 Completion PR 完成前不得释放租约或启动后续任务。

## 目标

1. 保持唯一、机器可校验的 `specs/coordination/program-plan.yaml`；
2. 校验 Task、Wave、依赖、风险、POC、公共契约和最终发布闭包；
3. 将 Task Spec、Program Plan、Active Work、Completion Ledger 和 Git 历史绑定为同一控制面；
4. 证明 Reservation 真实建立租约且仅包含协调元数据，Implementation merge 已进入目标基线，Completion 只修改当前任务的窄范围元数据；
5. 保证 Active Work 的 Requirement、Module、Contract、output/shared path、Issue、Wave、风险和分支与 Program Plan 完全一致；
6. 保证后续 Wave 不在前序 Wave 尚未完成时启动，且活动状态转换相对目标分支只能改变当前任务允许字段；
7. 保证普通任务 Completion Ledger append-only，Foundation 使用独立且不可回退的完成模型；
8. 保证完成 Evidence 是本次完成流程产生、包含真实 merge SHA 和完成验证；
9. 只有 GitHub API 实际验证 main Ruleset 后，才允许将外部 blocker 标记为 resolved；
10. 将 Integrity、History、Transitions、Finalization、Coordination Dispatcher 和 Scope Dispatcher 同时接入 Governance Gate 与 `make verify`。

## 非目标

- 不改变冻结产品需求；
- 不冻结具体业务 OpenAPI、Event Payload、DDL 或 Workflow；
- 不实现业务代码或执行 POC；
- 不修改生产环境、Secrets、权限策略或正式数据；
- 不关闭 OPS-001 #20，也不声称 GitHub Ruleset 已启用；

- [ ] 后续 Wave 不得在任何前序 Wave 任务仍未完成/取消时启动；同一 Wave 可在容量约束内并行。
- [ ] 相对目标分支的活动转换只允许当前任务的合法状态变化，不得改写其他 Program Task、Registry policy 或其他 Lease。

- [ ] ordinary completion 只追加自己的不可变 Ledger 记录；Foundation 不修改普通 Ledger。
- [ ] Completion PR 只能修改当前任务的 Plan 状态、自己的 Lease、Task Spec、Ledger（普通任务）和 Evidence。
- [ ] 完成 Evidence 的 Handoff、Summary、Commands、Test Results 均在 Completion PR 刷新，并记录真实 implementation merge SHA。
- [ ] schemaVersion 2 completed Foundation Task Spec 不得回退为 approved；只有真实 legacy Foundation 可保留历史状态。
- [ ] Ruleset 的 `~DEFAULT_BRANCH` 根据 live repository default branch 解析；include/exclude 条件正确应用到 `main`。
- [ ] Ruleset 必须要求最新目标分支检查和最新推送独立批准；API 不可用或规则不足时 fail-closed。
