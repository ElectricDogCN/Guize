# GZ-014 收敛项目交付计划并加固多 Agent 协作一致性

## 背景

GZ-003 已建立需求索引、模块所有权、活动任务登记和协作检查，但合并后仍存在多套后续任务定义、公共机器契约写入者不唯一、任务依赖和退出门禁无法完全机读等缺口。GZ-014 的 Program Plan 实现已通过 PR #21 合并，但该 PR 在最新 Codex 复审完成前被合并；复审随后确认 8 个额外协作门禁缺口，因此 GZ-014 继续保持 `in_progress`，不得释放 Registry 或启动后续任务。

## 目标

1. 保持唯一、机器可校验的 `specs/coordination/program-plan.yaml`；
2. 覆盖 GZ-004～GZ-020、POC-001～POC-010 和 M0～M6 的依赖 DAG；
3. 明确 Requirement、Module、Contract Namespace、Task、POC、Acceptance 的追踪关系；
4. 明确公共契约唯一 owner、consumer 与显式 shared writer；
5. 校验波次容量、high/critical 上限、依赖完成态、路径所有权、外部 blocker 和契约生产/消费；
6. 将 Task Spec 退出门禁与 Program Plan 精确绑定，并要求 completed 任务具有可验证完成记录；
7. 让后续 Agent 只从 Program Plan、Task Spec、Registry 和 Evidence 恢复工作；
8. 修复 PR #21 合并后 Codex 对最新提交提出的全部阻断项。

## 非目标

- 不冻结具体 OpenAPI、Event Payload、DDL、Workflow 业务内容；
- 不实现 Java、Python、前端、播放器或 Go 业务代码；
- 不执行硬件、存储、AI、网络或恢复 POC；
- 不修改生产环境、Secrets、权限策略或正式数据；
- 不扩大 bootstrap allowlist 绕过 Registry；
- 不关闭 OPS-001 #20 或声称 GitHub Ruleset 已启用。
