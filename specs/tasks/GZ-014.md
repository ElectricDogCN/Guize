# GZ-014 合并后 Readiness 与多 Agent 协作恢复

## 背景

GZ-003 通过 PR #11 合并后，`main@9e3a821ada292ac3ef69b7c059384d17f6530b48` 的 Governance Gate run #106 失败。失败项为 Project Readiness：需求索引和模块所有权索引存在四条非对称映射。由于 Project Readiness 是所有 PR 的强制步骤，该缺口会阻断正常 Reservation PR，也证明 GZ-003 合并前缺少“真实仓库索引必须通过”的回归测试。

同时，GitHub Ruleset 列表为空，仓库内 CI/CODEOWNERS 尚不能平台级阻止管理员在红灯状态合并；重复 GZ-003 PR #13 仍维护另一套协作实现，形成双重权威风险。

## 目标

1. 修复 Requirement/Module 双向映射，使真实仓库 Project Readiness 恢复成功；
2. 增加直接验证仓库真实索引的回归测试；
3. 将 GZ-004～GZ-012 的直接依赖切换为 GZ-014，阻止红灯基线上并行开工；
4. 关闭重复 PR #13，只保留 `specs/coordination/**`、`check-agent-coordination.py` 和单一 Governance Gate 为权威协作实现；
5. 形成需求、设计、机器契约、POC、实现、多 Agent 协作和 GitHub 外部控制的最终启动审查；
6. 明确 Ruleset 仍为管理员外部阻断项，不将文档或 CODEOWNERS 误报为平台强制。
