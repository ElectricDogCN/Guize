# GZ-014 Foundation 生命周期状态修复

## 背景

GZ-014 的实现修复已通过 PR #26 合并为 `ef1048344aa082c678e5ef948dc7f62e5aa84510`，合并后的 `main` Governance Gate #267 成功。准备执行 Foundation Completion 时发现当前治理模型存在不可达状态：

- Program Plan Schema 的 Foundation 状态只允许 `in_progress / blocked / completed`；
- Lifecycle Guard 只允许从 `review / integration` 进入 `completed`。

因此当前 GZ-014 无法在不绕过门禁的情况下完成。必须先让 Foundation 使用与普通任务一致的审查和集成状态，并用回归测试固定该状态机。

## 目标

- Program Plan Schema 允许 Foundation 使用 `review` 和 `integration`；
- 保留 `completed / in_progress / blocked` 现有语义；
- 用实际 Program Plan 样本验证 Foundation `review`、`integration` 可通过 Schema；
- 用历史感知生命周期测试验证 `integration -> completed` 可执行；
- 不在本 PR 中改变 GZ-014 Program 状态，不释放 Lease，不关闭 Issue；
- exact-head Gate、fresh Review、expected-head merge 和 post-merge `main` Gate 全部成功后，再依次执行 review、integration、completion 元数据 PR。

## 非目标

- 不修改产品需求、业务机器契约、业务代码或部署；
- 不改变普通 Program Task 生命周期；
- 不直接将 GZ-014 标记为 completed；
- 不启动 GZ-004、GZ-010 或其他下游任务；
- 不降低 Completion Evidence、Issue、Commit 或历史验证要求。

## 风险

- 只修改 Schema 而不验证历史感知 completion 会制造新的不可达状态；
- 放宽到任意字符串会破坏 fail-closed；
- 在同一 PR 中提前更改 Program 状态会混合实现和生命周期迁移；
- stale Evidence 会误导后续 review/integration/completion。

## 回滚

合并前关闭 PR 并保留分支。合并后通过独立 Revert PR 撤销 Schema 与测试；不得直接推送或重写 `main`。
