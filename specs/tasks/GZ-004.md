# GZ-004 冻结 V1 需求、NFR、验收与追踪基线

## 背景

GZ-014 已完成并释放 Foundation Lease，且治理兼容修复 PR #35 已合并后通过 `main` Governance Gate run #331。GZ-004 Reservation PR #36 已合并为 `56d6bfacba45d36e82376ebb5a5cea7394c88f0d`，post-Reservation `main` Gate #333 全绿。Guize V1 产品范围已经冻结，但正式研发仍缺少统一、机器可读的需求目录、非功能需求、需求级验收和 Requirement→Module→Acceptance→POC→Task 追踪合同。

## 目标

- 在不改变 `specs/requirements/product-requirements.md` 已批准范围的前提下，冻结十项 V1 需求的规范标识、别名、业务边界和非目标；
- 冻结安全、隐私、容量、性能、可用性、恢复、可观测、兼容性、维护性和供应链 NFR；
- 建立可机器验证的 Requirement→Module→Acceptance→POC→Task 追踪；
- 为 GZ-005～GZ-009、GZ-011 和后续实现提供版本化输入；
- 对尚未完成 POC 的性能、容量和兼容性指标显式标记为 `MEASUREMENT_REQUIRED`，不虚构生产阈值。

## 非目标

- 不改变 V1 产品范围、产品定位或 no-public-Beta 约束；
- 不冻结具体 OpenAPI、Event Payload、DDL、Workflow、LiteFlow、Worker 或 Plugin 内容；
- 不执行 POC-01～10；
- 不建立 Java、Python、Frontend、Player 或 Go 实现；
- 不修改生产环境、正式数据、Secret 或权限策略；
- 不把设计稿、预期值或 Agent 推断写成实测生产承诺。
