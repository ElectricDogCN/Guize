# GZ-003 需求设计一致性与多 Agent 协作就绪治理

## 背景

GZ-001 已建立仓库治理 Harness，GZ-002 已建立研发设计总基线。下一阶段将进入机器契约冻结、阻断性 POC 和业务实现。现有治理能够验证单个任务的范围、Evidence 和分支关联，但尚未管理多个 Agent 同时工作时的路径占用、任务依赖、基线新鲜度、角色分离、交接和集成顺序。

## 目标

1. 对冻结需求、专题设计、ADR、机器契约、WBS、测试和风险进行全链查缺补漏；
2. 建立需求追踪索引、模块所有权和实施就绪矩阵；
3. 建立多 Agent 活动任务登记、路径租约、依赖、风险、角色、交接和集成协议；
4. 将协作校验纳入 Task Spec、Prompt、Issue/PR 模板、Makefile、Governance Gate 和自动化测试；
5. 记录 GitHub 分支保护/Ruleset 等仓库外部设置缺口，不把未配置状态伪装成已启用。

## 非目标

- 不改变已冻结的 V1 产品范围；
- 不实现业务模块；
- 不虚构尚未评审的完整 OpenAPI、Event Payload、Flyway DDL 或生产配置；
- 不执行生产部署、正式迁移、Secrets 或权限策略发布。

## 协作与交接

- 本任务属于协作机制的 bootstrap，`coordinationMode=bootstrap`，不要求在尚未存在的活动任务登记中自登记；
- 实现者负责最小可验证变更，审查者负责独立检查需求优先级、误报/漏报和历史兼容；
- 交接记录写入 `evidence/GZ-003/handoff.md`；
- 合并前必须确认最新 HEAD 的 Governance Gate 成功、Review Thread 全部解决、活动任务登记无冲突。
