# GZ-010 建立十项 POC 的统一模板、样本、资源与排程

## 背景

GZ-010 Reservation v2 已通过 PR #45 合并为 `74ab9d53f29834fda37dcbd726fd58f997f8f21a`，post-merge Governance Gate #382 成功。当前阶段为正式 Implementation：建立 `POC-PROTOCOL-V1`、十项独立 POC 计划、资源/样本/结果索引、严格 Schema、Validator 和人类 README，但**不执行任何 POC**。

第一次 Reservation PR #42 的 Gate #374 暴露治理测试 fixture 缺陷并已关闭未合并；OPS-003 通过 PR #44 修复并由 Gate #380/#381/#382 在真实 Active Work 场景再次验证。该历史只作为失败与修复证据，不是当前实现结果。

## 目标

- 建立统一、机器可读的 `POC-PROTOCOL-V1`；
- 为 POC-01～10 建立一一对应的计划文件与独立 Evidence 边界；
- 固定环境、资源、样本、命令记录、原始结果、测量、退出条件、失败替代、安全/数据边界和审查字段；
- 保持 Program Plan 中 POC→Task→Requirement→Module→Wave/Risk/Dependency 的唯一映射；
- 让 POC-001～010 后续 Agent 可以在不重新解释范围的情况下独立执行。

## 非目标

- 不执行任何硬件、网络、存储、云、前端、AI 或恢复实验；
- 不填写真实实验命令、测量值、PASS/FAIL 决策或 Reviewer 结论；
- 不修改 REQ-V1/NFR-V1/ACCEPTANCE-TRACE-V1；
- 不创建 OpenAPI、Event、DDL、Runtime business contract；
- 不修改业务代码、部署、Secret、权限或生产数据。
