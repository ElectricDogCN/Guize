# OPS-006 建立 fail-closed Program Task Registration 生命周期

## 背景

OPS-005 / PR #51 证明：普通任务必须先存在于 canonical Program Plan 才能执行 `planned → reserved`，但现有 Harness 不支持通过独立、metadata-only PR 将一个不存在的任务登记为 `planned`。继续借用已完成的 GZ-003 会违反 completed-task immutable scope。

PR #53 首轮自举还暴露了 Project Readiness 将终态历史永久计入 Wave 容量的问题。该前置缺陷已由 OPS-007 / PR #55 修复，并在 `main@3acc6e4ee582f4fdee8ba90c630bf99eb870b252` 的 Governance Gate #446 验证通过。本任务不重复修改该修复。

OPS-006 本身采用一次性三阶段自举：Registration、Reservation/Activation、Implementation。Registration 只登记身份、范围与 DAG，不创建 Active Work Lease，不授权实现。

## 目标

- 定义并机器执行普通 Program Task 的 `absent → planned` Registration；
- Registration 只允许 exactly one 新任务及最小下游 DAG 追加；
- `planned` 始终是无 Lease、无实现权限的 metadata state；
- 保持既有 Reservation、Active Work、Review、Integration、Completion 与 Evidence 约束；
- 为 OPS-005 及后续维护任务提供可重复、fail-closed 的正式入口。

## 非目标

- 不实现 OPS-005、GZ-010 或 POC Program；
- 不修改业务、部署、生产数据或 Secret；
- 不提高任何并发或高风险上限；
- 不重新打开 completed 的 GZ-003/GZ-014；
- 不增加 skip、continue-on-error、allow-all 或 reusable break-glass；
- 不重复修改已由 OPS-007 完成的 terminal Wave occupancy 行为，除非独立回归证据证明其失效。
