# OPS-023 structure validation implementation design

This note is prospective Own design after the first activation commit d22d94b. The original Task body and original planning receipts remain unchanged. The already recorded delegated decision changes only local implementation start; actual reservation CI991/parent989 are still incomplete, and no POC permission is issued.

The first native working check retained 24 passes and 6 failures, with all three selected original regressions passing. Initial eligibility rejected every shared container identity. The real Program YAML and real original fixtures contain ordinary acyclic aliases, so this conservative implementation never reused their structure. The original Task/plan explicitly excluded aliases; the following is a declared local design refinement in the same two registered claims, supported by the independent review on 2026-11-07. It is not attributed retroactively to the old plan.

For this exact standard Program Schema, pure JSON value structure is independent of whether equal subtrees share a Python identity. Only the immutable key unfolds ordinary acyclic shared values. Never mutate or replace the actual caller document or its aliases; a cold miss runs the original complete validator on that original object. Every hit still checks the actual recovery.frozenAt using the current real validator/FormatChecker. All Task/Registry/role/lease/capacity/scope/history checks run normally outside this structure helper.

The key walk counts every expanded occurrence toward node and character limits, then bounds encoded UTF-8 size. Track containers on the current traversal path to reject cycles, rather than a global seen set that would reject harmless shared values. Non-JSON values, cycles, expansion budgets, unknown or changed schemas, custom validator classes/keyword dispatch/type checkers and frozen/non-active Programs retain full original validation. Keep only successful structure entries with bounded residency; format failures and other errors are not retained as negative verdicts.

The known effective full Schema text is pinned to SHA256 06778d02cf0be4abb4edd2aa382df3056c863e7be31b0589573ddc9792116c6f. The factory still reads it once and creates a fresh validator, resolver and FormatChecker. The optional source-text return preserves its original default API. No Schema contract, original test, workflow, runner, pin or 30-minute setting is changed.

The other initial new-test failure assumed the optional native date-time plugin was installed. The original native validator also accepted that format in the absence of the plugin. The new negative fixture now explicitly registers a deterministic date-time handler on a genuine standard FormatChecker and compares the original validator and helper using the same current instance. This adds no dependency or alternate production validation rule.

New regressions cover real aliased Program input, immutable expanded keys, shared-value mutation invalidation, original alias identity preservation, exponential alias expansion limits, cycle fallback, current format behavior, schema/validator changes, failures and real historical authority after a warm structure. Initial failures remain in the private raw record ops023-working-program-structure-v1. Corrected working checks and exact-fixture performance comparison are still required; local savings do not claim full official CI success. Code, Review and Completion retain complete official source and actual-main gates and independent review.

The second working run retained 31 passes and one new-test failure. Its reviewer-drift case correctly rejected the real mismatched entry, but the new assertion incorrectly expected every validation layer to use the outer label. The test now compares the exact real error list against a forced original complete-validation path on the same fixture/input. Production code did not change for this correction. This preserves actual Task/Registry labels and strengthens equivalence rather than inventing a new error-label contract.

The next working run passed all 32 selected tests. Independent static review then found a genuine eligibility bug: Python schema equality conflated boolean and numeric constants. Two new warm counterexamples, with unchanged source text and changed standard validator Schema, reproduced the missed errors. Schema identity now uses bounded type-faithful JSON value encoding, so `true`/`1` and `false`/`0` remain distinct and altered schemas return to complete original validation. The reproduction is retained separately; the new counterexamples join the full regression suite.
