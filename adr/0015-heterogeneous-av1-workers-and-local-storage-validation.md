# ADR-0015: 异构 AV1 工作池与本地 V1 验收

- Status: Proposed — GZ-021 实现候选；预留合并不等于路线或运行时已交付
- Date: 2026-10-13
- Task: GZ-021 / Issue #95

用户将首期编码资源调整为二手手机和闲置 Windows/Linux 设备，要求并行 AV1、HLS 切片缓存和播放优先调度，并授权本地 OpenList 模拟存储、百度云后置。采用独立编码工作池：归泽保留资产、版本、权限、任务和产物发布的权威状态，异构节点执行可替换的受限编码尝试。以明确版本化的本地验收配置验证功能，保留生产硬件、容量和外部服务义务，避免资源不可用阻断本地交付或模拟结果被当成生产通过。

## 概念与权威边界

| 概念 | 边界 |
| --- | --- |
| 业务编码任务 | 归泽所有；绑定输入版本、编码配置版本、主体、配额、优先级和取消意图 |
| 工作节点 | 可加入或退出的执行设备；报告实际验证的能力，不访问业务数据库 |
| 节点身份租约 | 证明节点会话仍有效；现有 WorkerLease 不能证明某个分片尝试有发布权 |
| 编码尝试租约 | 限定某段、某次执行和有效代数；超时重领后拒绝旧尝试的迟到写入 |
| 编码执行组 | 经连接点验证可组成同一连续 rendition 的工具构建、参数及媒体配置集合 |
| 播放需求 | 已授权会话对连续片段窗口的需求；多个会话可合并计算，但各自独立鉴权 |
| HLS 缓存 | 可重建的临时产物；READY 片段不等于完整、已保留的正式副本 |
| 正式 rendition/副本 | 经过完整性、全片连续性及发布校验后才登记的长期资产关系 |
| 验收配置 | 本地与生产测量、资源和结果声明的边界；不替代已有 DeploymentProfile 机器契约或媒体编码配置版本 |

## 决策

1. 节点使用出站连接领取受限任务，不共享数据库或 OpenList 管理员凭据。输入、输出引用限定资产版本、范围、目的地、有效期和配额；执行命令来自受控编码器配置，不能由任意用户字符串拼接。
2. Windows/Linux 稳定节点先承担播放和近期预取；手机按实际编码能力、温度、电源、网络和持续吞吐准入，先限制单任务。AV1 解码支持或编码器枚举不能代替编码试验；不能保证手机实时 AV1。
3. 规划器固定不可变输入版本/哈希、精确帧与时间边界和编码配置版本。4 秒 HLS 片长、约 32 秒后台工作块只是待测起点，不冻结为性能承诺。每个连续 rendition 固定经验证的执行组；不兼容的硬件/软件输出分开生成 rendition。
4. 统一校验与封装负责帧数、随机访问、初始化/codec configuration、PTS/DTS 和累计解码时间轴，以及完整连接解码。音频使用连续时间轴；单片可解码不能证明全片连接正确。只广告已经 READY 的连续播放区间，完成前不声明完整 VOD。
5. 产物先写尝试专属临时区域，校验后以当前租约代数单次发布。重复完成幂等；过期、已取消或旧代数回报不覆盖 READY。失败、断线、重启和源版本变化必须有可验证的重试、拒绝或恢复结果。
6. 保留原 P0～P8：PLAY_NOW/PLAY_AHEAD 使用 P0，PREWARM 使用 P3，OFFLINE 使用 P6。用户主动冷恢复仍为 P1，主动转码/字幕/AI 仍为 P2。按主体公平、额度和播放截止时间调度，后台等待提升不能侵占播放保留容量。
7. 首期整块编码按非抢占估时处理，使用后台槽位；只有实现安全子段发布和检查点退出后才在子段边界让出。不能承诺任意帧暂停。预计赶不上播放时使用已可播放版本或经批准和测试的兼容编码路径，AV1 后台继续。
8. seek 生成新的会话窗口代数并撤销旧窗口需求，不取消其他观众仍需要的计算。窗口按连续 READY 区间扩展，拒绝迟到窗口更新；不制造未完成片段空洞或改变已发布 URI 的既有时间轴。
9. manifest、init、segment 与缓存命中均先鉴权，撤权后热缓存也拒绝访问。稳定缓存键绑定输入/配置版本、执行组、轨和段号；令牌不进入共享对象键或日志。产物源站与缓存不得提供匿名绕过入口。

## 本地与生产验收

机器可验证的验收配置只允许 `local-v1` 与 `production`，绑定配置版本、权威修订和对应资源/测量；未知配置、错配或缺失必要绑定默认拒绝。本地成功不能满足生产发布门禁。

本地使用真实 OpenList、数据库、编码器和播放器验证功能与可控故障；小容量测试采用显式配置且可测的水位，不静默降低生产 500GB 安全空间要求。OpenList 只是测试来源和存储入口，不承担归泽 ACL、正式副本账本或生产恢复权威。约 700TB 来源规模、ESXi/A380、TrueNAS/iSCSI、真实手机/物理跨机持续性能、公网和百度生产接入分别保留待测或后置记录，不以本地服务健康、模拟目录数或单机实验替代。

本地 V1 仍覆盖全十项需求、十二项验收以及权限、数据完整性、幂等恢复、真实 AI/检索、规则/配置、备份恢复和供应链。GZ-021 仅修订已登记的权威规格、设计、POC 和原始规划 manifest 指定的未启动定义；后续 GZ-008 定义执行协议，相关正常任务实现运行时。原生产 GZ-020 义务保留。

## 取舍与后果

继续以单一 A380/ESXi 路线作为本地编码前提，会把平台功能交付绑定到暂不可用的设备；直接让异构节点各自编码并拼片，则把配置和时间轴不兼容、迟到结果与权限错误转嫁给播放器。本方案换取节点可替换和资源复用，同时增加执行组验证、尝试 fencing、统一封装、需求合并及公平调度的责任。

节点类型多不等于故障域多：一台物理机上的 Windows 与 WSL 只证明独立进程的协调。实际手机温升、后台生存性、跨物理机故障和客户端 AV1 播放必须分别实测。缓存可重建，也不能降低正式副本的完整性、保留和恢复要求。

## 验证与生效

规格正负回归必须拒绝未知验收配置、错误配置绑定、伪造生产测量和不安全水位；运行时任务另验证节点中断重领、迟到/重复完成、取消、源更新、seek 窗口、完整 HLS 连续性、兼容回退和热缓存撤权。

验收证据按 POC、profile、version 分开。原共享结果索引只描述 POC 任务进度，不授予生产证据合同；本地记录由原 POC 所有者保存，后续生产记录由 GZ-020 在自身 Evidence 中以显式 schemaVersion 2 保存，不覆盖完成历史。profile 索引绑定所有者、实验、结果引用及范围，完整里程碑必须校验所选范围的全部十项证据，不能用 local-v1 完成状态代替生产测量。生产 POC-001/002 在原 A380/ESXi 项之外承接异构兼容、真实 Android 观测及其版本绑定；原生产数值与义务不降低。

本 ADR 随受独立审查的 GZ-021 路线实现合并后生效。任何设计声明都不构成 POC、生产发布或完整本地 V1 的通过记录；结果必须绑定实际源码、样本、工具、环境、命令和测量。
