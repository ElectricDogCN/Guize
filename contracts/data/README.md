# PostgreSQL 数据契约

DDL 由 `data/migrations` 中的 Flyway 迁移维护。每个模块拥有自己的 PostgreSQL 命名空间。跨域外键用于数据库必须始终维护的身份关系，跨域业务操作仍通过平台接口执行。数据库标识沿用 OpenAPI 的不透明字符串格式，数据库中的修订号从 1 开始。

## 来源与资产身份

| 逻辑实体 | PostgreSQL 表 | 约束 |
| --- | --- | --- |
| `source_data_source` | `source.data_source` | 来源默认私有，所有者为 IAM 标识 |
| `source_object` | `source.object` | 来源与提供方标识组合唯一；缺少提供方稳定标识时，由来源模块生成稳定标识 |
| `source_object_history` | `source.object_history` | 每条记录对应来源对象的一次修订 |
| `asset_asset` | `asset.asset` | 当前内容版本必须属于该资产；新资产可在同一事务内先生成身份再绑定版本 |
| `asset_version` | `asset.version` | 版本号在资产内唯一，来源对象和前序版本可查 |
| `asset_duplicate_group` | `asset.duplicate_group` | 相同内容可共享重复组，资产仍保留自身身份 |
| `asset_content_hash` | `asset.content_hash` | 完整、抽样及提供方摘要分别记录 |

当前路径支持长 UTF-8 路径和等值查找，采用 Hash 索引避免对长路径使用 B-tree 键。重命名和移动更新来源对象并追加历史，资产版本只在内容变化时创建。来源停用或删除的业务流程保留来源身份与历史，通过状态反映可用性。

[来源与资产数据库验证](../../specs/contracts/data/verify_source_asset.sql) 在已迁移的隔离数据库执行，只使用合成记录并在结束时回滚。

## 资产别名、标签与归并证据

`asset.alias` 直接投影来源的旧路径和文件名。改名和移动只追加来源历史，查询可按长 UTF-8 路径等值匹配。若来源随后关联到另一个资产，别名仍由同一来源历史派生，并返回该来源当前关联的资产。调用方通过来源及资产的现行权限过滤，别名本身只是搜索材料。`asset.tag` 在命名空间内按大小写折叠去重。`asset.tag_assignment` 每条只绑定资产或来源之一，历史来源和各自的标签保持独立。

`asset.version_source` 保存已确认的资产版本、来源对象及其精确修订和读回证据。当前视图只返回仍匹配资产当前版本和来源绑定的证据。新记录先核对资产，再调用来源模块的受限锁函数，最后核对版本摘要。受限函数不向资产角色授予来源表权限。历史归属保留。需要为旧数据补充关联证据时，由来源读回后正常登记，禁止倒推未观察的来源修订。已验证的版本来源和全量摘要历史不可原地改写。

`asset.merge_decision` 保存两个资产的当前内容版本及当时修订、决策、操作者和可选摘要证据。写入以资产标识的稳定顺序锁定两端，并分别核对期望修订。批准要求两端权威全量摘要及长度一致。新增全量验证证据与消费该证据的关联或归并事务在对应版本行协调，避免锁等待期间仍使用旧摘要结论。既有的冲突摘要原样保留，`asset.authoritative_content_hash` 只返回无歧义的算法证明。拒绝决定可在没有相等摘要的情况下记录。应用层仍需核对两端和所有来源的授权、保留保护与策略，再按各模块服务执行真实归并或拆分。决策记录及来源标签无需改变已发布的资产版本归属。

V9 不重建已有路径或摘要历史。恢复环境先核对现有版本及新增表和视图，再校验 Flyway。已应用环境通过备份恢复或前向修订演进。[数据库验收语句](../../specs/contracts/data/verify_asset_classification_and_merge_evidence.sql)

## 来源同步与检查点

`source.capability` 按来源记录已观测能力及连接器版本。`source.credential_reference` 保存经过授权的 OpenBao 引用和修订。`source.sync_policy` 为每个来源保存可追溯的策略版本。`source.sync_request` 把 `source.sync.v1` 任务绑定到指定来源、策略、扫描分区和模式。新来源可以在第一个资产出现前开始扫描。已有任务的资产绑定保持有效，其他任务仍需输入版本；无资产的来源同步由来源平台控制面执行，无法选择媒体执行计划。

每次执行在 `source.sync_job` 留下一条记录，重试使用新尝试编号和独立标识。同一来源和扫描分区只能有一个运行中的尝试。平台负责划定不重叠的扫描分区并按策略限制尝试次数。已结束的尝试不能重新进入运行态。`source.sync_checkpoint` 对同一来源、策略版本、分区和模式保留各自进度。控制面从修订号 0 开始，在同一次事务内提交页面观察、所需事件和检查点。事务先调用 `source.record_sync_checkpoint`，按任务、来源、尝试顺序锁定并比对持久化修订，返回新修订，再保存页面观察和事件。其他需要同时修改这些状态的事务沿用此锁顺序。任务已离开运行态、来源停用、旧尝试或过时修订均抛出 `40001`，调用方须退出当前保存事务并重新读取已提交进度。空游标表示该扫描分区无后续提供方游标，仍有持久化修订。对账扫描不能覆盖增量扫描游标。

连接器只通过平台接口交付观察，游标是仅供受保护来源控制面读取的提供方数据。任务模块通过 `task.lock_running_source_sync` 提供受限状态检查和行锁，只适用于来源同步。部署将该函数归任务模块角色所有，仅授权来源控制面执行，来源控制面不需要 `task.task` 表权限。两项函数均撤销公共调用权限。V7 保留 V1 至 V6 的记录及既有资产绑定，经备份恢复和迁移校验确认。已经应用的数据库通过前向修订或恢复受测备份演进。[来源同步验证](../../specs/contracts/data/verify_source_sync_state.sql) · [有限角色验证](../../specs/contracts/data/verify_source_sync_control_role.sql)

## 任务计划、租约与结果

- `task.task` 以所有者与操作作用域内的幂等键去重，引用同一任务的当前计划。`task.execution` 保存外部工作流与运行标识。
- `task.plan` 和 `task.plan_step` 保留历史版本。每个计划和步骤标识只有一个当前步骤版本。尝试绑定实际节点、能力版本、协议、输入及步骤版本，fencing 在该步骤版本内递增。
- 控制面按任务行、步骤行、租约行的顺序锁定并更新。修改当前计划、步骤或任务状态的事务先锁同一任务行，修改租约的事务遵循同一锁顺序。任务领取使用 `task.lease_attempt`，返回新 fencing。已有活动租约或步骤已经接受结果时返回空值。节点心跳与执行租约分别保存。
- 控制面验证调用主体后使用 `task.accept_attempt_result`。过期、换代、已请求取消或绑定不符的尝试返回 `REJECTED`。首次存储返回 `ACCEPTED`，精确重放返回 `REPLAYED` 且无写入。记录结果与关闭租约在同一事务执行。节点通过平台协议提交，数据库函数仅供有权限的控制面调用。

[任务计划与尝试验证](../../specs/contracts/data/verify_task_plan_and_attempt.sql) 使用合成任务检查上述约束并回滚。

## 节点资源账本

`task.resource_pool` 以节点和资源标识记录容量、占用及已扣记预算。`task.resource_reservation` 绑定实际尝试、数量和有效期。控制面在同一派发事务取得任务租约与必需的容量预留，任一预留失败时回滚整个派发。多资源预留按资源标识排序，预留有效期受执行租约约束。

`task.reserve_resource` 在同一资源池行锁中核算余额并建立单条预留。相同预留请求返回 `REPLAYED`，复用既有记录。控制面通过 `task.settle_resource` 一次记录实际扣记量及释放理由，同时更新资源池。临时槽位和空间按预留量归还。执行时长预算保留实耗，未使用部分归还本预算池。已过期的记录仍须由控制面结算或回收。两个函数只授予控制面所需权限。

[资源账本验证](../../specs/contracts/data/verify_task_resource_accounting.sql) 覆盖节点归属、共享编解码槽、预算上限、释放及重复调用。

## 派生物血缘与事务 Outbox

`ai.derived_artifact` 将一个清单条目绑定到已接受的尝试、步骤、输入版本和清单摘要。资产身份由该输入版本解析，平台读取每次检查资产当前访问权限。清单条目键由控制面从已验证清单取得，同一尝试的同一条目只建立一个派生物。派生物的各版内容独立保存，人工修订与发布状态变化通过追加版本记录。追加者持有当前修订，按修订号递增。

`outbox.event` 保存事件信封所需字段，`outbox.event_envelope` 提供发布所需 JSON。尝试首次接受和派生物发布分别在同一业务事务写入对应契约事件。发布服务通过待发布记录重试，接受服务对同一结果的精确重放不新增事件。事件传输允许重复，消费者在自己的事务中按 `event_id` 去重。`outbox.consumer_offset` 记录逐事件完成，消费者不能只用分配时的顺序号作为提交进度。

V5 只扩展契约。升级为旧版已经接受的结果补建事件，保留持久化的接受时间和清单摘要。当前尝试接受事件使用固定阶段修订 3，fencing 仍由执行租约独立分配。未来的尝试事件写入需共用修订分配。备份恢复真实数据时先复验迁移历史与数据约束。前向修订保留已接受结果、历史内容和事件记录。

结果接受沿用调用者权限。控制面需要任务读写和行锁权限、接受函数执行权限、接受事件投影视图的查询权限，以及 `outbox` 命名空间和 `outbox.event` 插入权限。派生物发布控制面同样需要事件插入权限。发布服务只读待发送信封，发送成功后更新 `published_at`。消费回执写入者只写自己的逐事件完成记录。具体角色由部署环境授予，节点只通过平台协议接入。

验收环境的 Flyway 校验使用 `ignoreMigrationPatterns=repeatable:pending`。已应用的版本化迁移在校验时必须仍然存在，并匹配原校验和。旧版本的数据备份先用对应版本恢复，再按原顺序迁移。

## 用户、会话与资产 ACL

`iam.user_account`、`iam.role` 和 `iam.group` 各自保存身份。角色能力、用户角色和组成员关系独立去重。IAM 按经过规范化的用户名查找账户。密码只通过不透明凭据引用取得，Passkey 持久化公开认证材料。会话以不透明 Cookie 的摘要查找，用单独的摘要校验 CSRF，认证方法以行记录。轮换和撤销保留旧会话的失效时间。

`iam.asset_acl` 按资产、用户或组或角色、操作记录唯一的授权或拒绝，主体参照实际身份记录。请求处理依据当前资产修订和 ACL 计算授权。派生物通过输入内容版本取得同一资产身份。IAM 在控制面完成主体展开、优先级判定与审计。源凭据、令牌原文和私钥的存储仍由专用密钥服务承接。

V6 增加身份和 ACL 表，保留现有资产、任务及会话启用前的数据。发生未合入前的迁移问题时撤回候选。已应用环境用备份恢复或前向修订演进。

## 媒体表现、完整缓存与正式副本

`media.profile` 保留已批准的不可变配置版本。`media.rendition` 绑定资产输入版本的完整 SHA-256、准确配置版本和输出摘要及长度。媒体表现的同一标识不能改绑，发布状态必须引用通过的 `media.quality_result`。`media.track` 保留轨道索引、编解码器、语言及持续时间。AV1 工作单元调度、HLS 清单组装和逐分片授权由媒体及边缘模块联调。

`storage.backend` 区分缓存位置和正式位置，引用固定的部署目标及故障域。`storage.cache_entry` 只保存完整文件缓存及固定缓存。完整回读必须匹配权威资产版本长度及已验证的完整摘要，确认测量证据之后才进入可用状态，并在同一事务将 `cache.complete.verified` 写入 Outbox。ATS Range/Slice 和 HLS 临时分片不属于完整文件缓存或正式副本。缓存淘汰角色只获 `storage.advance_expired_cache` 执行权，于 TTL 到期后把普通缓存按期望修订推进为 `EVICTING`，确认缓存字节处理后推进为 `EVICTED`。固定缓存、未到期缓存和正式对象不能通过此函数淘汰。

`storage.replica` 绑定已知媒体输出及正式目标，上传状态与验证状态分别记录。正式副本的读回长度和 SHA-256 均应与绑定输出相同，验证结果与 `replica.verified` 同事务提交。归档 `storage.retention_policy` 版本与 `storage.retention_hold` 历史。数据库串行化同一资产的保留保护与正式副本状态变更。已回读副本的移除申请和状态确认均检查保留期限、活动保护，以及其他故障域的可用正式验证副本。同一故障域内的目标、上传未验证副本和隔离副本不能满足该检查。缓存淘汰无需拥有这些正式生命周期表的权限。

`storage.migration` 记录同一媒体表现的副本迁移，`storage.watermark_event` 保存目标的实测水位。数据库持久化状态与完整性门槛。外部操作模块执行普通缓存淘汰时重新确认可重建性。`DELETING` 表示数据库登记了移除请求，文件操作模块仍需执行真实删除前的保留、权限和替代副本核对，并处理操作中断后的恢复。实际字节回读、存储水位阈值、外部对象操作和恢复演练分别按所属模块与 POC 验证。V8 保留已应用数据。回滚时从固定备份恢复或以前向修订演进。[数据库验收语句](../../specs/contracts/data/verify_media_storage_state.sql)
