# Plugin 与制品锁 V1

核心先验证平台版本与同版 Worker schema、SDK 和一致性向量的摘要。插件仍使用现有 `guize.plugin/v1` Manifest。制品锁另行绑定插件 ID、Manifest 原件、发布区间、不可变制品、远端仓库和提交、Task、签名证明、SBOM、许可证及验证证据。锁使用已固定版本。平台兼容区间包含下限，排除上限。

插件和节点由运行时分别发现及探测。缺席、版本不兼容、验签失败、Manifest 或制品不符、启动异常和能力未知均只影响相应入口。核心可在空注册表启动。只有锁内且通过运行检查的能力进入调度。停派时先撤销相应能力，再等待或请求取消当前尝试。旧组合需从已验制品锁恢复；数据保留及恢复由各自模块负责。

能力包固定运行时、配置、可选模型、许可证和输出契约。媒体分析和离线 OCR 绑定已批准的采样或质量配置，并继承源授权。离线包可以通过本机进程接口消费，禁止经 Manifest 扩大到外部网络。实际目的地权限来自 Worker 的受限授权，真实帧样本、OCR 精度及资源阈值沿用后继审批。

离线校验比对所提供的实际文件摘要。部署端提供已验签的观测、真实启停结果和探测能力。Android、Windows、Linux 可以分别验证；联合验收使用三方实际制品和同一组锁定证据。主仓保持对版本组合及授权的决定权。
