# 整条媒体链路观测候选与当前实施决定

2026-10-26 更新：独立复核当前 Docker 内核 `6.18.54.1-microsoft-standard-WSL2` 后，确认精确版本的 [page_counter.c](https://raw.githubusercontent.com/microsoft/WSL2-Linux-Kernel/linux-msft-wsl-6.18.54.1/mm/page_counter.c) 仍以分离的比较和写入更新 watermark。并发交错可能由较小的陈旧写覆盖较大值；这是源码推论，并非 V5 已复现此竞态。故 `memory.peak` 不作为严格保守上界，扩大输入、完整进程组或重复读取均不能补足该保证。本页后续容器方案仅保留为隔离与辅助观测候选，停止按它直接生成正式 `maximumBufferedBytes`。V5 的匿名子进程峰值保留结论保持原有限范围。

当前优先完成已有同步 allocator 账本的真实路径覆盖：确切构建的分配/共享所有权/释放表、首次媒体处理前及收尾窗口、原生完整记录，以及 origin/gateway/client/export 的有依据容量界限。未知 external 事件继续使结果失效；不猜误差余量、不把内存限制当观察值、不改冻结校验。具体只读判断另归档在 `evidence/POC-003/representative-cache-forward/`。

当前只有有限匿名内存 canary V5 的结果获接受：真实 exec 子进程释放并退出后，原生峰值仍保留90,316,800字节。它证明本机 Docker 的计数可用，不证明 ATS、原15项或完整媒体域。本文件明确下一段实现及待验证的条件；不批准新镜像、输入、资源或实验。

## 实现边界

完整沙箱放进一个新建私有容器，由一个只处理控制元数据的 PID1 监督进程管理。所有媒体处理者从首次 exec 起就在同一个 cgroup，重启、清缓存和临时工具也不换组。复用原 lab、collect、缓存观察/导出及撤权实现；不另造媒体服务或改变冻结 checker。

| 处理者 | 必须纳入的工作与终止事实 |
| --- | --- |
| 输入准备子进程 | 流式产生固定版本输入、写全并核实际哈希/长度；完成后真实 wait |
| lab 控制器 | origin/gateway 及其线程、授权控制、启动/停止记录；完成后真实 wait |
| ATS 与插件 | stock ATS、Slice、CRR、缓存查找观察和导出；每次启动、配置验证、clear 和重启均留 PID/argv/退出事实 |
| collector | 原冻结矩阵、并发请求、实际 body 写入、源区间比对与哈希 |
| 缓存与记录组装子进程 | 所有导出 body 读取、重建、完整/partial 证据及媒体派生事实计算；不能把这些读取留到观测窗口外 |
| PID1 监督器 | 创建与绑定组身份、只读原生计数、控制收尾；不读取、生成或转发受保护媒体正文 |

监督器不得在容器内使用 Docker socket、host PID/network、特权模式、额外 capabilities、可写 cgroup 或任意 shell。初始身份按 V5 保留实际 Linux/PID/UID/GID/groups、四组 kernel UID/GID、capability 与 NoNewPrivs 原件；允许的组列表只能为空或主组1000，不能暗放其他组。

## 输入、存储与页归属

镜像只装已固定版本的代码、ATS/Python 运行依赖和非媒体配置。不能将预热媒体放入镜像层，或从别的进程继承已经承载媒体的共享映射、匿名区、IPC 或描述符。

测试输入由组内独立准备子进程在全新私有磁盘目录中流式产生，逐字节核对事先固定的两个版本、长度和哈希。可以先准备并审核同内容样本，但不能把外组缓存页/文件映射直接当本次组内媒体。实际使用的每个输入、缓存和临时文件必须来自本次新目录、新对象和组内首次写入；不复用旧 run、宿主媒体挂载或外部共享缓存。

使用专属、空的磁盘存储承载较大输入和输出，不能把全部输入/raw 放进受内存限制的 tmpfs。若使用 Docker 私有卷，必须先证明该卷为空、只被本次沙箱使用，且 UID1000 的实际所有权/权限正确；卷初始化中不能混入媒体。卷及原始结果在失败后保留。只读根文件系统和实际可写数据目录分别核验，不能以配置标志代替实际权限。

共享页最初可能记在其他 cgroup，单凭进程属于当前组不足以证明覆盖。实际 source、映射和存储流必须排除该漏洞；必要时采用有限共享页反例验证拒绝路径。未建立该归属证明，不得把原生计数填成正式 maximumBufferedBytes。[内核的内存归属说明](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory-ownership)是该条件的依据。

## 原生计数与每次请求

在任何媒体子进程启动前固定实际容器 ID、镜像摘要、cgroup 目录 device/inode、PID/cgroup namespace、PID1 出生标识及实际资源设置。保持一个只读 memory.peak 描述符，不重置、换组或扣减启动基线。

每份观察保留实际 memory.current/peak/max、swap.current/max、events/local、成员及必要原生身份。配置 memory.max 只是限制，不能冒充峰值；OOM、非零 swap、身份变化、缺失/超限原件、峰值倒退或未确认的退出都使结果失败。压力/回收事件及超过配置上限的真实峰值原样保留，不能截断到上限。[内核接口说明](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory-interface-files)定义这些计数。

collector 在请求实际完成之后读取原生计数，并保留该请求的真实单调时钟边界。并发请求可以按实际捕获顺序串行保存；不能因它们的完成顺序不同而改写时间。计数累计覆盖短命子进程，不能用周期 RSS 采样、用户态 chunk 大小或单个 ATS pool 小计代替。

原始流保留完整 EOF/wait 与实际文件长度/摘要。短写、配额或截止导致的前缀必须标为不完整并失败；不把内存中的待写字节冒充已落盘原件。可复用 V4 已实际故障验证的有界非阻塞收集方式。

## 完整媒体窗口与收尾

窗口起点早于第一个媒体准备子进程。停止顺序为：停止新请求、完成或中止当前工作、关闭所有媒体文件/管道、实际 wait 每个媒体后代、确认组中只剩从未接触媒体正文的监督器，再做最后原生捕获。异常、取消、超时和 quota 都进入同一个有界收尾；只操作本次保留的进程身份。

所有需要读取正文的哈希、缓存重建和事实组装必须在媒体子进程内、最终捕获前完成。监督器只能在捕获后处理不含正文的记录、摘要和控制元数据，不得再开媒体文件。其后实际容器退出也须由外部控制器确认并保留原件。

这一候选方法证明的是完整媒体处理窗口的上界。监督器最后仍存活时组并非空；不能声称观察到了最终空组，或将窗口末峰值冒称容器退出后整个组的最终峰值。是否以“所有媒体处理者已退出、监督器不再触碰媒体”的完整证明替代旧方案的空组观察，仍需针对实际代码获得独立数域接受。没有该接受就保持未资格化。

## 与原15项及资源配置衔接

原矩阵、partial 不提升完整缓存、源更新、缓存清理、权限隔离和同源热缓存撤权继续执行。延迟使用未加 strace 的真实路径，时间戳来自实际响应；原生计数读取不能改写或伪造首字节/完成时间。最终正式记录只使用实际原件计算出的字段，不设置“假定通过”。

prototype-64m-v1 的两哈希、64MiB、256MiB cache 及原预算保持。representative-v1 已能绑定较大真实输入；具体大小、cache 容量、内存/磁盘/请求/输出预算和窗口须在执行前固定。输入必须大于获接受的缓冲上界，cache 也必须实际容纳矩阵所要求的完整对象；不能只让输入验证通过，却忽视缓存覆盖。

首轮可评估224MiB对象、160MiB运行内存上限、192MiB缓冲上界及现有256MiB cache 的组合。这仅是执行前候选：真实工具启动占用、cache 有效容量、磁盘余量、页归属与原协议相容性尚需核实，没有数值批准或运行结果。观察值始终取真实计数；资源改变只能前向重新固定和批准，保留旧失败，不能改弱原 checker。
