# 归泽 V1 界面契约

[页面与操作表](../../specs/ui/ui-contract-v1.yaml) 定义 19 个页面。每项操作以已发布 OpenAPI 的 `operationId` 绑定方法、路径、权限、状态、错误和验收。节点注册和心跳保留在工作节点协议，管理台工作节点页使用 `listWorkers`。仪表、配置及其权限以各自已发布契约为准。

## 页面与模块状态

- 登录和公开资产使用各自的公开、限流接口。连接器、资产、工作队列、媒体、缓存、AI、搜索和配置有自己的加载和失败状态。
- 页面区分加载中、可用、空数据和暂不可用。插件缺失、启动异常或其服务不可用时，在对应区域说明影响并保持其他区域可用。页面获得的数据依其已授权范围渲染，切换会话或资源时重新取数。
- 页面显示和操作提示使用接口权限声明。请求由 API 根据会话、资源范围、二次认证和审批结果执行。权限错误落在当前操作，继续保留用户有权限的页面与操作。

## 操作反馈

- 普通成功进入可用状态。HTTP 202 进入等待处理状态，通过既有任务查询或事件流更新进度。播放计划的可播放响应和仍待处理响应分别呈现。Passkey challenge 成功进入下一步挑战，任务事件接口成功进入流式状态。
- 错误反馈引用 `ERROR-CATALOG-V1` 的错误码、适用语言和可重试标志。401 进入会话处理，403 反馈权限限制，404 使用统一的不可用状态，409 提示冲突，429 提示限流。失败只影响发出该操作的界面区域。
- 任务事件流断开时可重新取已存在的任务状态，再显示恢复后的进度。以已发布的任务和播放接口作为状态来源。

## 复验

运行 `python specs/ui/check_contract.py` 检查全部操作的归属和权威引用。追加 `--json` 可获取解析后的操作、权限、HTTP 结果、错误及验收映射。检查只读取仓库契约文件。运行 `python -B specs/ui/test_contract.py -v` 可复验四个拒绝场景及播放等待、Passkey 挑战和任务事件流的三个响应状态。

当已发布接口、权限、错误或验收映射改变时，先检查受影响操作，再更新映射和绑定摘要。UI 路由是客户端导航约定，API 保持既有版本及入口。运行期插件注册、播放和权限联调在各自的集成阶段完成。
