# 09. 媒体、AV1 与在线播放 / Media, AV1 and Streaming

## GZ-021：本地完整 V1 与异构媒体执行

AV1 编码解耦为受限异构 Worker 池。节点通过实测能力准入，而非按 OS 或 GPU 名称推断兼容性。同一 Rendition 的跨度必须固定输入版本/哈希、编码器构建和参数、关键帧策略、色彩、帧率/时间基准、音轨及字幕处理。不同构建或能力组先完成初始化段、跨边界音画同步与整片解码验证，再允许共同产出。

4 秒分片、32 秒编码跨度只是首轮实验配置，须由实际媒体/设备测量调整，不能承诺通用速度或手机性能。跨度边界必须可独立解码；服务端核验初始化配置、时间轴、输出哈希和当前尝试后才发布。包含音频/VFR/HDR 的配置需要各自样本验证，不能沿用无音频合成样本的结论。

播放调度采用 P0 当前及临近播放窗口（PLAY_NOW/PLAY_AHEAD）、P3 预热（PREWARM）、P6 离线/后台标准化，并保留平台原 P1/P2 类别。预留播放槽位，后台任务有老化/公平份额和预算上限。已运行编码以跨度完成、超时或可确认取消为边界；不声称任意抢占 FFmpeg。播放不足时选择已有源/Rendition 或 H.264 回退。

Manifest 只曝光同一版本连续 READY 窗口；乱序完成不能留下空洞，只有全部完成才能发布 ENDLIST。seekEpoch 隔离旧播放需求，attempt/fencing 隔离旧执行结果。清单、初始化段、分片和缓存命中都必须鉴权，过期/撤权后失败关闭，不能直接回源绕过。A380 保留为生产节点能力，生产 POC 内容仍有效。

## 1. 播放策略

播放计划按顺序选择：

```text
浏览器直接支持的已有 Rendition
→ AV1 直接播放
→ 已有 HLS/DASH ABR
→ 已准入能力组的临时 H.264 Worker
→ 已授权源媒体回退（客户端支持时）
→ 明确失败和修复建议
```

不为所有文件预先生成所有格式。

## 2. 媒体探测

`ffprobe` 结果记录：

- 容器；
- 视频/音频/字幕流；
- 编解码；
- Profile/Level；
- 分辨率；
- 帧率；
- 时长；
- HDR；
- 色彩；
- 音轨；
- 字幕；
- 旋转；
- 关键帧信息；
- 异常和可播放性。

探测结果关联源版本和工具版本。

## 3. AV1 标准化

### AV1 Master

目标：

- 长期存储；
- 高质量；
- 保留关键音轨和字幕；
- 作为后续 ABR 输入；
- 记录编码器、参数和质量。

### AV1 ABR

按实际内容和设备生成 Ladder，不固定所有档位。输入考虑：

- 源分辨率；
- 帧率；
- 内容复杂度；
- HDR；
- 目标设备；
- 带宽；
- 转码成本。

## 4. 生产 A380 节点角色

Arc A380 用于：

- AV1 硬件编码；
- H.264 兼容编码；
- 解码加速；
- 关键帧；
- 缩略图；
- 媒体预处理。

必须通过 POC 测试：

- ESXi 6.7 直通；
- 驱动；
- QSV/VAAPI/oneVPL；
- AV1 质量；
- 多并发；
- 首分片时间；
- GPU 重置；
- 长任务稳定性；
- 功耗和温度。

未通过 POC 前，不在文档中承诺性能数字。

## 5. 临时 H.264

只在客户端不支持现有 Rendition 时启用。

特点：

- 当前播放按 P0 调度，平台其他既有优先级按类别保留；
- 边转边播；
- 临时分片；
- 任务结束后按 TTL 清理；
- 热度足够时可触发正式兼容 Rendition；
- 不自动作为长期保留。

## 7. ATS Range/Slice

ATS 负责：

- 缓存块对齐 Range；
- 减少重复回源；
- 热门片段加速；
- 分散大文件 IO；
- 统计字节命中率。

必须测试：

- 206；
- 200 回退；
- If-Range；
- ETag；
- 源内容变化；
- 缓存污染；
- 不同权限；
- 超大对象；
- 中断恢复。
